# Operational signals and private HTTPS

The application emits actual Prometheus request count, response status and latency metrics, normalized to route templates instead of ticket IDs. `/metrics` also checks database/schema readiness and reads the sanitized local backup-status file. Structured JSON request logs include request ID, method, normalized route, status, duration and release. Credentials, query strings and ticket bodies are omitted.

`compose.monitoring.yaml` supplies Prometheus, Grafana, Alertmanager, PostgreSQL exporter and Caddy. Include it with the main Compose file; use `.env.example` only as a template and replace passwords. The application continues to work without this override. All administrative listeners bind to loopback; PostgreSQL exporter has no published port. Native PostgreSQL is the currently verified runtime; the monitoring containers have not run because a local container VM could not be created within the available disk space.

Prometheus scrapes the app and exporter every 15 seconds and retains seven days. Grafana provisions one six-panel dashboard: DB readiness, request rate, 5xx rate, p95 latency, local backup age and PostgreSQL connections. A zero backup timestamp means none; it is not an elapsed recovery measurement. Sparse traffic can leave rate/latency panels empty. No synthetic success metrics are emitted.

Five rules cover missing app, unavailable DB/schema, elevated 5xx under sufficient traffic, missing/stale/failed backup evidence and exporter outage. Controlled-series tests cover unavailable service, unavailable DB/backup and healthy silence; they validate expressions, not a notification channel. Alertmanager's local receiver deliberately has no destination. Before an external notification claim, configure an authorized receiver with secrets outside Git, inject an appropriate private lab failure, and verify both delivery and resolution.

Local checks run on 2026-10-14: Prometheus 3.15.0 `promtool` syntax, five alert-rule definitions, three controlled-series test groups and Alertmanager 0.34.1 `amtool` configuration passed. The container config's `/etc/prometheus/alert-rules.yml` cannot resolve on the host; native syntax-only validation plus the separate actual rule checks cover that boundary. Tools were downloaded from official GitHub releases with published digest verification into ignored `.tools/`. No live scrape/Grafana runtime or external alert delivery was verified.

Caddy source listens on container port 8443, mapped to host loopback 8443, and proxies to app:8000. Its internal CA is for a private lab; certificate generation/trust have not run. Retrieve the CA through an authorized private session and use an explicit trusted CA for CLI verification. Do not disable verification or bypass browser certificate warnings as evidence. Public HTTPS requires an access-control and domain/DNS review plus separate deployment authorization.

Images are controlled by exact version tags in Compose. The application delivery path additionally requires an immutable digest. Container images/tags must be pull-verified and dependency digests reviewed when Docker becomes available.
